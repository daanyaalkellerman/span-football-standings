# Production readiness review

Review date: 13 October 2026. Scope: the assessment PDF, AGENTS.md, requirements checklist, historical research, data provenance, both historical CSVs, Maven configuration, all four production Java files and all three JUnit test files. This was a critical review of the actual implementation by Codex, not an external human audit. No Git staging, commits, pushes or publication were performed.

## Findings and correction

One reproducible defect was found in `Main`: supplying a filesystem root as the output path caused an uncaught `NullPointerException` because its parent is null. This was reproduced before editing. The CLI now rejects root paths, directories and existing non-regular output files with a clear error and exit code 1 before creating a temporary output. Ordinary file output is unchanged. No calculation defect was found.

Modified Java files: `Main.java`, `MainTest.java` and `HistoricalIntegrationTest.java`. No changes were made to the historical input, existing historical output, Maven configuration, AGENTS.md, or calculation/parser classes.

## Implementation decisions checked

- Match dates are validated metadata; all supplied matches are counted. The historical cutoff belongs to the dataset, not the calculator. Teams are exact, case-sensitive names; aliases are not silently merged.
- Statistics use long integers, two points per win and one per draw. Checked additions protect accumulated goals, appearances and points. Wins/draws/losses are bounded by appearances. Individual input scores are limited to nonnegative Java int values.
- Equal-point goal averages are compared with BigInteger cross-products, avoiding overflow and rounded-decimal comparisons. Goal difference is not a ranking criterion. Exact ties share competition positions (1, 1, 3); alphabetical order only stabilizes display.
- Positive goals with zero conceded rank as infinity. A 0/0 record displays N/A and compares as zero. Finite averages display two decimal places with HALF_UP rounding. These approved conventions are documented application choices, not newly established historical rules.
- The reader requires the exact five-column header, accepts UTF-8, an optional initial BOM, LF/CRLF, quoted commas and doubled quotes. Each record must occupy one physical line. Empty/header-only files, blank/missing fields, invalid dates/scores, self-play, malformed quotes and duplicate date/home/away keys are rejected. Conflicting scores for the same key are rejected too.
- Output uses the agreed ten columns, UTF-8 and LF. Input is completely read and validated before writing. A sibling temporary file is moved into place, using atomic replacement when supported, with a non-atomic replacement fallback. Temporary files are cleaned up on normal failure paths. Same-file input/output and output symlinks are rejected.
- Usage errors return 2; input/output/validation failures return 1; successful execution returns 0. Errors go to stderr and successful execution is silent.

## Test assessment and additions

All original 40 test invocations were inspected. Calculation tests assert explicit statistics and ordering, including cases where goal difference or rounded ratios would give a wrong answer. CSV tests exercise malformed records and preservation of an existing output. Historical expectations are a fixed, source-transcribed 22-row table, not values generated by the production calculator. Internal totals are useful consistency checks but do not independently prove historical truth.

Three regression/coverage tests were added:

1. Root and empty-directory output paths are rejected clearly and preserve the directory.
2. Quoted headers, a valid leap date and distinct return fixtures are accepted.
3. A real CLI subprocess with reversed historical input order, paths containing spaces and a French locale produces the fixed expected historical output, exits successfully and emits no console text.

## Cross-platform assessment and limitations

Production code uses Java Path/Files and explicit UTF-8; it contains no Windows paths, user directories, PowerShell calls or shell commands. Tests locate Java through java.home. Maven compiles for release 21; JUnit is test-only and there are no third-party runtime dependencies. The documented classpath invocation works with a Java 21 JDK and Maven on a Unix-like system without a Windows shell dependency. This review ran on Windows only: macOS/Linux execution and a clean checkout on the reviewer's machine remain unverified.

The implementation keeps all matches in memory and is intended for small league datasets. Multiline quoted fields, automatic alias normalization, points deductions and date filtering are outside its documented contract. Permission-denied, disk-full, concurrent filesystem changes and the non-atomic move fallback were not fault-injected; missing paths and directory failures were tested. Atomicity cannot be promised when the filesystem requires the fallback. Symlink/hardlink guards were inspected but not separately exercised in this review.

Historical source independence and period-rule uncertainties remain as documented in data/SOURCES.md and HISTORICAL_RESEARCH.md. A second arithmetic implementation validates calculation, not fixture provenance. The known reference-table Arsenal/Tottenham ordering discrepancy and Leicester/Chelsea display-rounding differences are already documented; no new historical discrepancy was found.
